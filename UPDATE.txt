DEPLOYING UPDATES VIA DOCKER HUB
=================================

Alternate to the default `./update` flow (see README.md). Builds images on
your dev machine, pushes to Docker Hub, Pi just pulls and runs them.

Docker Hub user: keenansegenchuk (repos: uptonair-flask-server, uptonair-nginx)

Run all commands below from the repo root.

--------------------------------------------------------------------------
ONE-TIME SETUP
--------------------------------------------------------------------------

1. Create Docker Hub account + repos `keenansegenchuk/uptonair-flask-server`
   and `keenansegenchuk/uptonair-nginx` (auto-created on first push if
   missing).

2. SSH into the Pi and run:

       uname -m

   - `aarch64` -> platform `linux/arm64`
   - `armv7l`  -> platform `linux/arm/v7`

3. On dev machine:

       docker login
       docker buildx create --name pi-builder --use
       docker buildx inspect --bootstrap

--------------------------------------------------------------------------
EVERY TIME YOU WANT TO PUSH AN UPDATE
--------------------------------------------------------------------------

Step 1 — On dev machine, from repo root (PowerShell):

    cd client
    npm run build
    cd ..

    docker buildx build --platform linux/arm64 ` -f dockerhub/Dockerfile --target flask-server ` -t keenansegenchuk/uptonair-flask-server:latest ` --push .

    docker buildx build --platform linux/arm64 ` -f dockerhub/Dockerfile.nginx ` -t keenansegenchuk/uptonair-nginx:latest ` --push .

  (Substitute `linux/arm/v7` if that's your Pi's platform. Optionally tag
  with a version, e.g. `:1.4.0`, instead of/alongside `latest`.)

Step 2 — On the Pi, from repo root:

    cd ~/UptonAir
    git pull

    docker compose -f dockerhub/docker-compose.yml --env-file .env pull flask-server nginx
    docker compose -f dockerhub/docker-compose.yml --env-file .env up -d

--------------------------------------------------------------------------
ROLLING BACK
--------------------------------------------------------------------------

1. Edit the `image:` tag(s) in `dockerhub/docker-compose.yml` to the older
   version.
2. On the Pi:

       docker compose -f dockerhub/docker-compose.yml --env-file .env pull flask-server nginx
       docker compose -f dockerhub/docker-compose.yml --env-file .env up -d

--------------------------------------------------------------------------
CHECKLIST / GOTCHAS
--------------------------------------------------------------------------

- Always include `-f dockerhub/docker-compose.yml --env-file .env` on
  every `docker compose` command for this flow.
- Never run both this flow's `up` and the root `docker-compose.yml`'s `up`
  at the same time (port conflict on 80/443).
- Run `npm run build` in `client/` before every push — the nginx image
  bakes in `client/build`, so a stale/missing build gets pushed otherwise.
- If you add/change env vars in the root `docker-compose.yml`'s
  flask-server service, mirror the change in
  `dockerhub/docker-compose.yml` — they don't stay in sync automatically.
- Certs (`certs/cert.pem` / `certs/key.pem`) and `.env` are bind-mounted /
  injected at runtime, never baked into the images.
- `pgdb` uses the official `postgres:17` image as-is, nothing to build.
